### 0. Scope & dependencies

This builds the **shared substrate every other story stands on** — the parts of the design that are owned by no single story and must exist, correct, before the story bodies can be built or tested. Per [`../001-analytics-platform/PLAN-INDEX.md`](../001-analytics-platform/PLAN-INDEX.md), the ingest front-door depends on "— (foundation)"; every other story depends transitively on it and therefore on this. It delivers: the canonical envelope contract type + wire-version handling (Foundation §1.1); the BullMQ-on-Redis queue wiring and fast-ack door (FR-006, backbone §3); the **9-step canonical worker op-ordering skeleton** (Foundation §3.1) as a shared kernel with typed-kind routing to consumer hooks (steps 1–6 + the routing seam; steps 7/8 story-body additions are owned by the story dirs but wired here); the **Redis key grammar + data-type palette + open-day bucket lifecycle + rehydrate-on-miss + seeded-marker machinery** (§2); the **flusher + M/N/S/L flush-class merge engine** (§3.2/§3.2.1); **skew-correction + slewing-NTP clock discipline + sanity clamp + monotonicity alarm** (§4.2); **day-seal + quarantine** (§4.3); the **two dedup regimes** (§4.1); **provenance §4.5 derivation** from credential class; the **platform logical-day §4.7** floor; the **ER skeleton tables shared by all** — `GAME`, `EXCEPTION_TALLY`, `EVENT_CATALOG`, `EVENT_DAY_COUNT`, plus the operational entities `IDENTITY_EDGE`, `ERASURE_LEDGER` (Foundation §1.2, ER-full); **scale/backpressure/rate-limiting** (ops-envelope §2–§6); **GDPR erasure (Q7 four-tier + `ERASURE_LEDGER` + job)** and **DSAR-access job** (ops-envelope §7/§9); **Postgres PITR backup** (FR-028/ops-envelope §8); **envelope-encryption of reversible secrets + TLS + operator hardening surface + default-deny PII** (FR-029/ops-envelope §9); and the **`docker-compose` skeleton** bringing the whole stack up (SC-009).

**FR/SC this substrate is accountable for:** FR-006 (fast-ack queue-backed door), FR-008a (dedup regimes — mechanism substrate), FR-008b (skew-corrected event-time + seal + quarantine substrate), FR-009 (write-ahead ordering position in the op-order), FR-010 (results-only store split — enforced by the schema shape), FR-011 (Redis AOF/noeviction posture), FR-011a (idempotent absolute-value flush + classes), FR-027 (config knobs incl. set-once `reporting_offset`), FR-028 (Postgres PITR backup), FR-029 (out-of-DB secret encryption + TLS + operator hardening), FR-030 (GDPR Art. 15/20 access), SC-007 (results-only storage), SC-008 (Redis-loss superset guarantee), SC-009 (single `docker-compose up`). #### 1.8 The flusher + M/N/S/L flush-class merge engine (Foundation §3.2 / §3.2.1 — highest rigor)

- [ ] **T-00.45** Implement the **flusher** as a BullMQ repeatable job on `flush_interval` (default 5 min) that sweeps the per-domain dirty-registries and upserts absolute values; a retried/duplicated flush must be a **no-op by construction** under every class — *cite:* Foundation §3.2, FR-011a.
- [ ] **T-00.46** Encode the rule **"deltas never flush; only absolutes do"** — anything not expressible as an absolute cell must be a durable-immediate (step 7) write instead — as a design/lint guard on new flushed structures — *cite:* Foundation §3.2.
- [ ] **T-00.47** Implement **class M (monotonic-additive)** merge: `SET value = GREATEST(target.value, EXCLUDED.value)`, `HSETNX` seed, no atomic read required (torn-low read self-heals) — *cite:* Foundation §3.2.1 class M.
- [ ] **T-00.48** Implement **class N (non-monotonic / mutable-down)** merge: per-bucket monotonic `gen` (small integer column on class-N result rows), seeded from the durable row's `gen` on rehydrate and `INCR`'d inside every atomic block that can move a cell down (MOVE, FX-recompute); the flush reads all cells **and** `gen` in one **Lua `EVAL`** snapshot (uninterruptible); upsert tagged with the snapshot `gen`, rejected `WHERE EXCLUDED.gen ≥ target.gen` — `GREATEST` **forbidden** here — *cite:* Foundation §3.2.1 class N. *(bucket-key hash-tag `{game_id:mon:day}` noted as future Redis-Cluster concern — flagged §4)*
- [ ] **T-00.49** Implement **class S (set-membership)** merge: `members = target.members ∪ EXCLUDED.members` (set-union, never blind replace), `SADD` seed; HLL sketches under the scale lever merge via `PFMERGE` identically — *cite:* Foundation §3.2.1 class S.
- [ ] **T-00.50** Verify **class L (LWW-guarded)** path is unchanged: day-less per-user snapshot guarded by `as_of` (`SET … WHERE EXCLUDED.as_of ≥ target.as_of`), per-entry rehydrate — the `as_of` guard is a generation gate by another name — *cite:* Foundation §3.2.1 class L (verified unchanged). *(structure owned by [004-economy](../004-economy/spec.md); kernel confirms the guard shape)*
- [ ] **T-00.51** Implement the **mixed per-field merge for `EVENT_CATALOG`** (`cat`, day-less): `count`/`last_seen` by `GREATEST`, `first_seen` by **`LEAST`** (an earlier first-seen must lower it), `property_type_sets` by **union** — a single class label does not fit — *cite:* Foundation §3.2.1 (mixed structure), [design.md](./design.md).
- [ ] **T-00.52** Encode the **class-assignment gate**: every flushed structure declares its class (M/N/S/L or per-field); adding a flushed structure requires stating its class — as a contribution/CI check — *cite:* Foundation §3.2.1 (fixed here; a story never re-chooses its class).
- [ ] **T-00.53** Implement the **seal-time final flush** that finalizes a day's cells, after which the read model stops consulting Redis for that day — *cite:* Foundation §3.2, §2.3, §3.3.
- [ ] **T-00.54** Implement the **read-model live-vs-historical merge** applied once uniformly: sealed days from Postgres only; open days live from Redis buckets, falling back to last-flushed Postgres on missing bucket (post-crash) — *cite:* Foundation §3.3. *(story read-models state WHAT they read, not a new merge rule)*

#### 1.9 Skew / clock-discipline / seal / quarantine / dedup machinery (Foundation §4)

- [ ] **T-00.55** Implement the skew-correction formula: `skew = server_received_time − client_sent_time`; `corrected = client_event_time + skew` (only if `|skew| > 60 s`); `corrected = min(corrected, server_now)` (future-clamp); `bucket = logical_day(corrected)`; `corrected` stored as UTC epoch — *cite:* Foundation §4.2, FR-008b.
- [ ] **T-00.56** Implement the **sanity clamp**: an event whose corrected time moves > `clock_sanity_max_hours` (default 26 h) from `server_received_time` is bucketed on `server_received_time` + `time_fallback` tally rather than trusted — *cite:* Foundation §4.2 (guard 1).
- [ ] **T-00.57** Implement the **monotonicity alarm**: a worker observing `server_received_time` move backward between consecutive batches raises an operational alert (the stepped-clock failure this guards) — *cite:* Foundation §4.2 (guard 2).
- [ ] **T-00.58** Implement day-seal + quarantine substrate: a logical day mutable until `D_end + 48 h` then seals; sealed-day / typed-invalid events append to the raw quarantine tail with marker + tally, **never folded** into any aggregate/spine bit/catalog count — *cite:* Foundation §4.3, §2.3.
- [ ] **T-00.59** Implement the **drop-vs-quarantine** decision helper: drop-and-tally (not raw-appended) = unparseable/empty-name/cap-exceeded; quarantine (raw-appended + marker + tally) = typed-invalid/sealed-late/`unknown_kind` — *cite:* Foundation §4.4.

### 4. Open considerations / flags for /plan (foundation kernel)

1. **Class-N Lua `EVAL` + Redis-Cluster hash-tag (Foundation §3.2.1 schema/deploy note).** The `gen` column on `MONETIZATION_CELL` / `PAYER_DAY` and the single-`EVAL` snapshot are single-node-Redis-safe today; if Redis is ever sharded to a Cluster, the `mon`/`rev` bucket key needs a hash-tag (`{game_id:mon:day}`) so all cells co-locate in one keyslot. Flagged by the design as below the no-DDL altitude — a /plan decision on the exact Lua script + key layout. **This is the single hardest piece of the flush engine — build and test class N before any class-N story ([006-monetization](../006-monetization/spec.md)) lands.**
2. **Kernel/story seam boundary.** The op-order kernel (T-00.33–44) is built here but its step-7/8 *bodies* live in the story dirs. There is a real sequencing hazard: the kernel must land with stub hooks and a stable routed-record contract **before** the story bodies can implement against it, yet its correctness (ordering, crash-safety) can only be fully tested once at least the ingest front-door (steps 1–6) is real. Recommend: build the kernel + step 1–6 realization (ingest) as one tightly-coupled unit, then open the step-7/8 hooks to the sibling stories. Foundation says steps 1–6 execute "in the ingest front-door" — the kernel and ingest are nearly the same buildable unit.
3. **Provenance depends on [011-operator-admin](../011-operator-admin/spec.md)'s credential registry.** T-00.61/62 cannot be end-to-end tested until [011-operator-admin](../011-operator-admin/spec.md) defines `GAME_SDK_KEY` / `GAME_SERVER_CREDENTIAL`. For the substrate build, stub the credential-class lookup behind the derivation interface so the op-order is testable before [011-operator-admin](../011-operator-admin/spec.md) lands.
4. **`reporting_offset` set-once enforcement mechanism (Foundation §4.7).** The design mandates set-once-at-install but the *mechanism* (a config-immutability guard once any data exists) is below the design altitude — a /plan decision. Getting this wrong silently re-buckets history and violates the seal invariant; it deserves an explicit guard + test, not a convention.
5. **PII scrubber placement + performance (ops-envelope §9).** The default-deny denylist + value-pattern scrubber (T-00.86) runs on the hot path **before** the raw-append (step 3/pre-step-4). Regex scanning every prop of every event at 600 ev/s design peak is a hot-path cost that needs a performance budget; the exact regex set and short-circuit strategy are /plan territory. Coordinate the exact placement with the ingest step-3 realization.
6. **Erasure cross-store write delegation (ops-envelope §7.5, §10).** The erasure job write-deletes structures owned by the story dirs — the system's second cross-story write delegation. The design ratifies this, but the transactional boundary (all-or-nothing across many owner tables, ordering `USER_SPINE` last) and the `awaiting_seal` re-evaluation loop are implementation-level and error-prone; recommend building the job only after all owner tables exist.
7. **Redis SPOF vs SC-009's "modest VPS" (ops-envelope §8).** Single un-replicated Redis is a 100 % ingest-outage availability ceiling on any Redis crash/OOM/reboot. Accepted for v1, but the operator-facing RTO (AOF-replay minutes) and the optional HA lever should be surfaced in ops docs at build time, not discovered in an incident.
8. **BullMQ `maxStalledCount` + job-id-on-raw-append interaction (Foundation §3.1 step 6).** The stalled-job re-run safety argument depends on every raw append carrying its batch `job_id` for rebuild-time collapse (T-00.32). The exact BullMQ retry/stall config and the job-id threading through the raw append are /plan-level and must be validated against the crash-window argument, not assumed.

This builds the **front-door of the whole platform**: the `/v1/events` ingest endpoint (fast-ack, key-auth → server-derived `game_id`/`provenance`, wire-`v` handling), the ingest worker's canonical steps 1–6 for **every** kind plus its own steps 7/8 additions for `generic`, the write-ahead raw day-file append (framed gzip, per-batch fsync, seal-driven rotation, quarantine tail, cold-off no-op), and the durable result tables `EVENT_CATALOG` / `EVENT_DAY_COUNT` / `EXCEPTION_TALLY` plus the `GAME` registry storage. It is the substrate every later story rides — per the [`../001-analytics-platform/PLAN-INDEX.md`](../001-analytics-platform/PLAN-INDEX.md) dependency table it **depends on nothing** and everything ([003-sessions](../003-sessions/spec.md)/[004-economy](../004-economy/spec.md)/[005-retention](../005-retention/spec.md)/[006-monetization](../006-monetization/spec.md)/[008-cold-storage](../008-cold-storage/spec.md)/[009-client-sdk](../009-client-sdk/spec.md)/[010-server-sdk](../010-server-sdk/spec.md)/[011-operator-admin](../011-operator-admin/spec.md)) depends on it. Prerequisites are infrastructure-only: Redis (AOF everysec + RDB, noeviction — Foundation §3.2), Postgres, BullMQ, and a running clock disciplined by a slewing NTP daemon (Foundation §4.2). The `GAME` row/credential entities are *stored* here but *written* by [011-operator-admin](../011-operator-admin/spec.md)'s admin API; a bare seed path is needed to test ingest before that exists.

**Accountable for:** FR-001 (fixed endpoint + key→game derivation), FR-002/FR-003 (isolation + auth-reject-nothing-recorded), FR-006 (validate+enqueue+fast-ack), FR-008 (accept-all + auto-catalog), FR-008a (`event_id` 24 h dedup; purchase durable gate *sequenced* here), FR-008b (skew-correct + clamp + seal-quarantine), FR-008c (drop vs quarantine + name-cap), FR-009 (write-ahead raw ordering), FR-010/FR-011/FR-011a (results-only + Redis-transient + idempotent flush — ingest's cells), SC-001 (register→see-counts <15 min), SC-002 (fast-ack independent of processing), SC-003 (zero cross-game contamination), SC-008 (Redis-loss superset guarantee). Provenance derivation (FR-004 identity, Foundation §4.5) is *consumed* here (stamped from credential class); credential lifecycle is [011-operator-admin](../011-operator-admin/spec.md).

- **`USER_SPINE.first_seen` / bitmap — written by [003-sessions](../003-sessions/spec.md), never by ingest (Q1, [bridge 02.5](../001-analytics-platform/bridges/02.5-activeness-spine-contract.md)).** Ingest's step 7 hands the routed session record to [003-sessions](../003-sessions/spec.md) which does sequence A (`first_seen` insert-if-absent) then B (bitmap bit). Reader dependency: ingest's `no_spine_row` check reads `USER_SPINE` (owned by [005-retention](../005-retention/spec.md), written by [003-sessions](../003-sessions/spec.md)).
- **Raw file lifecycle — ingest appends, [008-cold-storage](../008-cold-storage/spec.md) owns ([bridge 01.5 §1](../001-analytics-platform/bridges/01.5-raw-file-contract.md)).** Ingest executes step-4 append + seal-time decode-verify (T-01.32..T-01.39); **[008-cold-storage](../008-cold-storage/spec.md) owns** seal→upload→verify→bookkeeping→delete and `UPLOAD_BOOKKEEPING`. The handoff needs no lock: ingest only writes open files, [008-cold-storage](../008-cold-storage/spec.md) only ships sealed files. Rebuild-tooling erasure-refilter step (T-01.40 step 4) depends on `ERASURE_LEDGER` owned by ops-envelope/[011-operator-admin](../011-operator-admin/spec.md) (Q7).
- **Purchase durable gate — ingest sequences, [006-monetization](../006-monetization/spec.md) writes (Foundation §3.1 step 6).** Ingest owns *where* the `transaction_id` gate sits in the op-order (before any hot write); [006-monetization](../006-monetization/spec.md) owns the durable `PURCHASE_IDEMPOTENCY` insert-if-absent write + conflict semantics. Blocks full purchase-path testing until [006-monetization](../006-monetization/spec.md) exists.
- **`EXCEPTION_TALLY` — ingest owns, all stories write into it.** Ingest owns the table + writes tallies for other kinds' quarantines, but the reason-enum values `negative_offset` ([005-retention](../005-retention/spec.md) via [003-sessions](../003-sessions/spec.md)), `fx_stale_rate_used`/`fx_unconverted` ([006-monetization](../006-monetization/spec.md)), `rate_limited` (ops-envelope) are *produced* by those phases through ingest's tally path. T-01.4's enum must include all of them up front.

### 4. Open considerations / flags for /plan (ingest)

- **OF-1 — Missing `event_id` on a generic event ([design.md](./design.md) open Q1).** Design *default* = drop-and-tally under `unparseable` (an undedupable event would void the §F 24 h guarantee). The deeper sheet's "name + parseable body is enough" reading would instead accept-without-dedup. **Implemented as drop per the design default; flag for /plan if accept-undeduped is wanted.** Do not silently pick the other branch.
- **OF-2 — `first_seen` = `LEAST` merge direction (Foundation §3.2.1 mixed-`cat`).** The catalog flush MUST lower `first_seen` on an earlier observed value — the one field that merges by min, not max. Easy to get backward and would silently corrupt cohort/first-seen reads downstream. Called out as load-bearing in T-01.5.
- **OF-3 — Grand total as read-time Σ vs stored cell ([design.md](./design.md) open Q3).** §4 of the story lists a stored per-game×day grand total; the design derives it read-time from `EVENT_DAY_COUNT` (cap-bounded ≤500 terms, drift-free, raw-re-scan-free). **Implemented read-time (no stored cell); flag if a stored cell is preferred.**
- **OF-4 — Class-N Redis-Cluster hash-tag (Foundation §3.2.1 schema note).** Not ingest's cells (ingest is class M + mixed-`cat`), but if Redis is ever sharded the flusher's cross-domain assumptions must be re-checked; single-node posture (current) is unaffected. Noted for /plan awareness only.
- **OF-5 — Group-commit append-writer sizing ([bridge 01.5 §4](../001-analytics-platform/bridges/01.5-raw-file-contract.md)).** The single-writer-per-open-file + group-commit design is normative but the buffer/coalesce window sizing, backpressure when a writer lags, and the writer↔worker handoff mechanism are implementation-level (hot-path performance). Needs a concrete design at /plan: a slow disk fsync must not stall all workers for that game.
- **OF-6 — Seal-time decode-verify ownership seam ([bridge 01.5 §1/§4](../001-analytics-platform/bridges/01.5-raw-file-contract.md)).** The contract puts the end-to-end decode-check at the seal boundary "before upload-eligible" — but seal/lifecycle is [008-cold-storage](../008-cold-storage/spec.md)'s job while the append is ingest's. /plan must decide whether the decode-verify runs in ingest's seal-flush path or [008-cold-storage](../008-cold-storage/spec.md)'s nightly path (contract says "nightly/seal path"); pick one owner to avoid a gap where neither runs it.
- **OF-7 — Rebuild tool deferred but contract normative ([bridge 01.5 §5.1](../001-analytics-platform/bridges/01.5-raw-file-contract.md)).** v1 ships **no automated replay**; T-01.40 stubs the procedure as documented contract only. The mandatory `ERASURE_LEDGER` refilter step (step 4) depends on the ledger existing (ops-envelope §7 / [011-operator-admin](../011-operator-admin/spec.md)). Flag: "disposable-but-recoverable" is only real once the ledger schema is present, even though the tool is deferred.
- **OF-8 — PII default-DENY denylist content (§6 / ops-envelope §9).** The default `pii_prop_denylist` is non-empty (`[email, ip, phone, name, address, …]`) as of 2026-07-17 — the exact key list and the value-scrubber regex set are policy that /plan should pin explicitly (a too-broad regex strips legitimate props; too-narrow leaks PII into a 90-day raw file). Already-registered keys need the one-shot catalog-scrub tool (ops-envelope §9) which is a separate operator action, not part of this phase's ingest path.
- **OF-9 — Server-clock discipline is a deployment requirement, not code (Foundation §4.2).** Slewing NTP (`chronyd`, bounded `maxslewrate`, never step-on-start) is mandated for skew + seal correctness. Ingest's two software guards (26 h sanity clamp → `time_fallback`; backward-`server_received_time` monotonicity alarm) are in-scope tasks (T-01.22 + an alert), but the daemon itself is an infra/deploy prerequisite that must be in the docker-compose/ops runbook, not assumed.
