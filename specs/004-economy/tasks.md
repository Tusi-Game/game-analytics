## 0. Scope & dependencies

This story builds the **economy sink/source pipeline**: strict `economy`-kind payload validation, the hot `eco`/`bal` Redis accumulators, the flush to four durable structures (`ECONOMY_FLOW_RESULT`, `ECONOMY_FLOW_SEGMENT_RESULT`, `BALANCE_SNAPSHOT`, `ECONOMY_SUPPLY_DAY`), and the dashboard read model (source/sink/net-flow/sink-ratio, per-reason top-faucet/top-drain, currency depth, money-supply trend). It owns the `eco`+`bal` Redis domains and the four durable structures (Foundation §5, economy row). It rides the [002-foundation-ingest](../002-foundation-ingest/spec.md) substrate and consumes the routed record (Foundation §3.1) — so **[002-foundation-ingest](../002-foundation-ingest/spec.md) (ingest substrate: auth→`game_id`+`provenance`, write-ahead raw append, seal check, `event_id` dedup, catalog/tally front door) must be complete before any task here runs** (economy depends on the ingest substrate; references [003-sessions](../003-sessions/spec.md) for `session_id`/server-SDK trust path). Depth/supply also touch the `USER_SPINE` family as a **logical** (non-FK) parent (Q1: economy seeds no spine row).

**Accountable for:** FR-012 (record source/sink + currency/amount/reason), FR-013 (per game×currency×bucket: total source, total sink, net flow, sink ratio), FR-014 (per-reason top faucets/top drains), SC-004 (synthetic stream totals/net/ratio match hand-computed exactly). Contributes to SC-007 (results-only; depth is the sole opt-in per-user touch) and SC-008 (write-ahead ordering — inherited from the ingest substrate, not re-implemented here).

## 2. Cross-phase dependencies

- **From [002-foundation-ingest](../002-foundation-ingest/spec.md) (Foundation §5, §3.1 routed record) — READ:** economy consumes the *normalized routed record* (envelope + resolved kind + stamped `v` + corrected event-time/day + dedup-passed/seal-state verdicts). This story **reads** it as a key dimension; a body flag is ignored. → Blocks T-03.18, T-03.38 (trusted-only). Contingent on F-3 (resolved) — fallback `client` for valid-but-unclassifiable keys.
- **From `USER_SPINE` (Foundation §1.3, owned by [005-retention](../005-retention/spec.md)/written by [003-sessions](../003-sessions/spec.md)) — READ existence only:** `BALANCE_SNAPSHOT.user_id` is a **logical** parent (Q1: economy seeds no `first_seen`), so a balance row may exist with no spine row — no FK enforcement, no ordering guarantee. → Affects T-03.3, T-03.20.4, T-03.23 (must tolerate absent spine parent).
- **From the shared flusher (Foundation §3.2/§3.2.1) — this story registers structures, does not own the flusher:** `eco`/`eco:seg` as class-M, `bal` as class-L. → Blocks T-03.26, T-03.27.
- **From `level_bucket_boundaries` (shared config) — READ:** used at ingest to compute `level_bucket`. → Blocks T-03.19.
- **Feeds:** the dashboard read model only. **No** v1 story consumes economy results ([007-derived-kpis](../007-derived-kpis/spec.md) reads monetization, not economy). No structure this story owns is written by any other phase.

## 4. Open considerations / flags for /plan

- **T-03.44 — Tuple field encoding (impl detail, flagged in design).** The escaped-separator encoding for `eco`/`eco:seg` hash fields is left to /plan ("exact encoding is an implementation detail; unambiguity is the requirement"). Must round-trip `currency`/`reason` containing `:` without collision, and stay stable across a Redis rehydrate. — *[design.md](./design.md) Redis "Field encoding".*
- **T-03.45 — Currency-cap: `other` overflow vs drop-and-tally reconciliation.** The step-3 table says over-cap currency ⇒ **drop-and-tally `capexceeded`** (not raw-appended), while Foundation §2.3's observed-value-cap convention says over-budget values collapse into a counted **`other`** bucket (kept, not dropped). /plan must reconcile which posture economy currencies take (drop the event, or accumulate it under `other`), or confirm both apply at different layers (cap-registration drop vs display-time `other` collapse). — *[design.md](./design.md) Worker step-3 table row "currency cap" vs Foundation §2.3 "Observed-value cap + `other` overflow".*
- **T-03.46 — Provenance fallback edge [contingent].** Design flags `[OPEN — contingent]`: if the F-3 envelope/key-class decision leaves server keys indistinguishable, provenance defaults to `client`. F-3 is resolved (two prefix-typed classes), so the live edge is only "valid-but-unclassifiable legacy key ⇒ client". /plan should confirm the credential-class → provenance mapping surface the ingest substrate exposes on the routed record. — *[design.md](./design.md) provenance decision, Foundation §4.5/§9.5.*
- **T-03.47 — `sink_ratio` low-volume guard needs a per-leg event count.** The ratio annotation compares each leg's *event count* against `economy_ratio_min_events`, but the stored `amount_sum` cells hold summed magnitudes, not counts. /plan must decide the count source: reuse `EVENT_DAY_COUNT` (ingest substrate, per event-name, not per currency×flow — likely too coarse), add a per-cell count companion, or derive from another read. This is a genuine build-forcing gap. — *[design.md](./design.md) API sink-ratio row + spec §7 knob 2.*
- **T-03.48 — `ECONOMY_SUPPLY_DAY` capture moment (at-seal vs at-rollover).** Design names at-seal as the "lower-machinery option" but marks the exact capture-moment a plan-time detail. Confirm at-seal (reuse the seal sweep) and the percentile scan's scale lever (per-currency scan vs bucketed histogram) at expected user counts. — *[design.md](./design.md) API money-supply-trend row (Q5).*
