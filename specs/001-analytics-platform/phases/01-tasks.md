# Phase 01 — Implementation Tasks: Ingest + Raw Events / Catalog (+ 01.5 Raw-File Contract)
**Source spec:** `phases/01-ingest-raw-events.md`, `phases/01.5-raw-file-contract.md` · **Design deps:** `phases/00-foundation.md` (§1–§9), `spec.md` FR-001..011a / SC-001/002/003/008, `metrics/01-raw-events-catalog.md`, `phases/00.5-ops-envelope.md` §5 (rate-limit knob) · **Status:** task-list draft (2026-07-17)

## 0. Scope & dependencies

This phase builds the **front-door of the whole platform**: the `/v1/events` ingest endpoint (fast-ack, key-auth → server-derived `game_id`/`provenance`, wire-`v` handling), the ingest worker's canonical steps 1–6 for **every** kind plus its own steps 7/8 additions for `generic`, the write-ahead raw day-file append (framed gzip, per-batch fsync, seal-driven rotation, quarantine tail, cold-off no-op), and the durable result tables `EVENT_CATALOG` / `EVENT_DAY_COUNT` / `EXCEPTION_TALLY` plus the `GAME` registry storage. It is the substrate every later phase rides — per the README dependency table it **depends on nothing** and everything (02/03/04/05/07/08/09/10) depends on it. Prerequisites are infrastructure-only: Redis (AOF everysec + RDB, noeviction — Foundation §3.2), Postgres, BullMQ, and a running clock disciplined by a slewing NTP daemon (Foundation §4.2). The `GAME` row/credential entities are *stored* here but *written* by phase 10's admin API; a bare seed path is needed to test ingest before 10 exists.

**Accountable for:** FR-001 (fixed endpoint + key→game derivation), FR-002/FR-003 (isolation + auth-reject-nothing-recorded), FR-006 (validate+enqueue+fast-ack), FR-008 (accept-all + auto-catalog), FR-008a (`event_id` 24 h dedup; purchase durable gate *sequenced* here), FR-008b (skew-correct + clamp + seal-quarantine), FR-008c (drop vs quarantine + name-cap), FR-009 (write-ahead raw ordering), FR-010/FR-011/FR-011a (results-only + Redis-transient + idempotent flush — 01's cells), SC-001 (register→see-counts <15 min), SC-002 (fast-ack independent of processing), SC-003 (zero cross-game contamination), SC-008 (Redis-loss superset guarantee). Provenance derivation (FR-004 identity, Foundation §4.5) is *consumed* here (stamped from credential class); credential lifecycle is phase 10.

- [ ] **T-01.4** Define `EXCEPTION_TALLY` table: PK `(game_id, utc_day, reason)`, `count`; `reason` constrained to the Foundation §1.2 enum (`nameless|unparseable|capexceeded|quarantined_typed|sealed_late|time_fallback|negative_offset|no_spine_row|unknown_kind|fx_stale_rate_used|fx_unconverted|rate_limited`). ### D. Ingest API (`POST /v1/events`)

- [ ] **T-01.17** Implement `POST /v1/events` (single pinned path — no per-game URL): read credential from header, resolve `game_id` + `provenance` **server-side from the credential's class** (public `sdk_key` → `provenance=client`; `server_credential` → adds `provenance=server`). Note: `/v1` accepted for platform life; no v-sunset.
- [ ] **T-01.19** Enqueue the batch **opaque** to BullMQ and **fast-ack** `2xx {received: n}` — a queue-acceptance receipt, NOT a validation promise (all verdicts async, version-blind). — *cite:* FR-006, SC-002; 01 §Design API. (after T-01.17, T-01.18)
- [ ] **T-01.20** Enforce the per-game rate limit `ingest_events_per_sec_cap` (00.5 §5) at the door: on breach, whole-batch `429 + Retry-After` (admit-or-refuse atomically, never partial), increment `rate_limited` tally (arrival-day bucketed). — *cite:* 00.5 §5, Foundation §1.2 (reason enum); 01 §Design (`rate_limited` in enum). Note: throttle, not integrity control (00.5 §9).

### E. Ingest worker — steps 1–6 (front-door, all kinds) + steps 7/8 (generic)

- [ ] **T-01.21** **Step 1 — parse + resolved-kind.** Per-event envelope parse; `kind` default `generic`; the three reserved names (`economy`/`purchase`/`session`) **force the typed route regardless of declared kind** (§H-2 override); unrecognized `kind` → `unknown_kind` quarantine. Empty/missing `name`, unparseable body, **missing `event_id`** → drop-and-tally (`nameless`/`unparseable`), never raw-appended. — *cite:* Foundation §3.1 step 1, §4.4, §1.1 open-enum; 01 §Design step 1 + OF-1.
- [ ] **T-01.22** **Step 2 — skew-correct.** `corrected = client_event_time + (server_received_time − client_sent_time)` with 60 s dead-band + future-clamp to server-now; unusable client times → `server_received_time` bucket + `time_fallback` tally (event still accepted); apply the 26 h `clock_sanity_max_hours` clamp. Bucket via `logical_day(corrected)` = `utc_day(corrected + reporting_offset)`. — *cite:* Foundation §4.2, §4.7; FR-008b; 01 §Design step 2.
- [ ] **T-01.23** **Step 3 — 01's realization order:** reserved-name override → `pii_prop_denylist` + `pii_prop_value_scrubber` + `pii_prop_hash` strip (forward-only, **pre-catalog, pre-raw**) → **name-cap gate** for new generic names (at `event_name_cap_per_game` → drop-and-tally `capexceeded`, decided **before** step 4) → typed strict required-payload presence check (invalid → quarantine-mark, proceed to step 4, then stop). Property-key cap: excess new keys ignored at catalog upsert, event still counts. — *cite:* Foundation §3.1 step 3, §4.4; 01 §Design step 3; §6 knobs; 00.5 §9 (default-DENY PII). **Cap gate before raw append — drops are never raw-appended.**
- [ ] **T-01.24** **Step 4 — write-ahead raw append** (see section F). Accepted *and* quarantine-marked events appended; drops never. fsync **before** any counter/spine/Redis write. — *cite:* FR-009, SC-008, Foundation §3.1 step 4, §E; 01.5 §4. (realized by F-tasks)
- [ ] **T-01.25** **Step 5 — seal check.** Corrected day already sealed (`> D_end + 48 h`) → append went to quarantine tail of the **current open file** → tally `sealed_late` (**arrival-day bucketed**) → stop. — *cite:* Foundation §4.3, §2.3; 01.5 §2; 01 §Design step 5 (arrival-day tally rule). (after T-01.24)
- [ ] **T-01.26** **Step 6 — dedup gate + crash-window ordering.** For `generic`/`economy`/`session`: claim `{game_id}:dedup:{event_id}` marker **before any counter/spine/hot write** (raw-append + dedup-claim form one recovery unit; duplicate → stop). For `purchase`: 01 owns only the **sequencing** — gate is 05's durable `transaction_id` insert-if-absent, placed before any spine/hot write, conflict → stop (05 owns the write). — *cite:* Foundation §3.1 step 6, §4.1, ST4 crash-window rule; FR-008a; 01 §Design step 6. (after T-01.25)
- [ ] **T-01.27** **Step 7 — routing seam (generic owns none).** For generic: **no** durable-immediate write; if the event carries a `user_id` with no `USER_SPINE` row, tally `no_spine_row` (advisory, never blocks). Hand the *routed record* (envelope + resolved kind + stamped `v` + corrected time/day + verdicts) to 02/03/05 at their step 7 for typed kinds; 01 seeds **no spine** (Q1). — *cite:* Foundation §3.1 step 7 ("the routed record"), §4.6; 01 §Design step 7; bridge 02.5. **01 writes nothing to the spine.**
- [ ] **T-01.28** **Step 8 — hot buckets (every accepted kind).** `cat` hash upsert (min `first_seen` / max `last_seen`, lifetime `count += 1`, property-type-set union) + `cnt` hash `HINCRBY` + `rank` zset increment — all rehydrate-on-miss. Quarantined typed events feed **nothing** (no catalog row, no day count). Then hand to routed story's step-8 accumulators. — *cite:* Foundation §3.1 step 8, §8.7; 01 §Design step 8; metrics §4 catalog upsert.
- [ ] **T-01.29** **Step 9 — ack** the queue job (after step 8). A crash between step 6 and ack → retried job is a dedup no-op → bounded undercount (approximate-OK). — *cite:* Foundation §3.1 step 9; 01 §Design idempotency note. (after T-01.28)
- [ ] **T-01.30** Implement the resolved-kind routing table (generic front-door-only; session/economy/purchase route onward at 7/8) and the **per-event verdict table** (`nameless`/`unparseable`/`capexceeded` → drop-no-raw; `quarantined_typed`/`sealed_late` → quarantine-raw-marked; `time_fallback` → accept-raw). — *cite:* 01 §Design routing + verdict tables, Foundation §4.4.

### F. Write-ahead raw day-file (01.5 contract — 01 executes the append)

- [ ] **T-01.32** Implement per-game × **corrected-UTC-day** file routing among **OPEN files only** (≤ 3 open/game under 48 h grace: today + 2 grace days). No append ever targets a sealed/COMPLETE/UPLOADED file. Sealed-late verdicts quarantine-append to the current open file with marker + offending corrected day. — *cite:* 01.5 §2, Foundation §2.3; conformance checklist item 1.
- [ ] **T-01.33** Implement the **single dedicated append-writer per open file**: serializes appends (one file, one writer — no interleaved/torn gzip members) and **group-commits** (coalesces multiple workers' appends into one fsync) so a hot single game does not collapse worker concurrency. Workers hand buffers to the writer. — *cite:* 01.5 §4 (fsync grain), conformance item 9.
- [ ] **T-01.34** Implement **framed gzip append**: each batch append is a self-contained, length-prefixed gzip member; codec = `raw_file_compression`, fixed for the file's life (codec change is forward-only, next day's file). Carry each record's stamped wire `v` and the batch `job_id`. — *cite:* 01.5 §4 (compression + framing), Foundation §1.1; conformance item 7.
- [ ] **T-01.35** Enforce fsync grain: **one fsync per dequeued batch**, fsync'd **before any counter/spine/money/Redis write for that batch** — counter-first is a bug. — *cite:* 01.5 §4, FR-009, §E, SC-008; conformance item 3. **The SC-008 superset invariant.**
- [ ] **T-01.36** Implement the record-class + marker vocabulary: **Body** (verbatim envelope, incl. duplicates), **Quarantine** (envelope + marker `reason ∈ {quarantined_typed, sealed_late}` + corrected day), **Drop** (never in file). Marker names **equal** `EXCEPTION_TALLY` reason names (one vocabulary); marker append precedes the tally increment. — *cite:* 01.5 §3; conformance item 4.
- [ ] **T-01.37** Implement file rotation by seal only: open at first append for its day, close at that day's seal (`D_end + 48 h`) → COMPLETE/immutable/upload-eligible. **No intra-day rotation.** — *cite:* 01.5 §4 (rotation), §6 (lifecycle); conformance item 2.
- [ ] **T-01.38** Implement **cold-storage-off** behavior: `cold_storage_enabled = off` ⇒ step 4 is a **no-op** (no file, no fsync, no lifecycle, no bookkeeping); counters/spine/money/tallies proceed unchanged; quarantine-destined events become **tally-only**; SC-008 superset waived (operator-accepted). Toggle forward-only (on-mid-day → partial file ships normally; off-mid-day → already-open file completes its lifecycle). — *cite:* 01.5 §7; conformance item 6; US5 scenario 3.
- [ ] **T-01.39** Implement seal-time end-to-end **decode verification** (every gzip member decodes) recorded in `integrity_ref` **before** a file is marked upload-eligible — a decode-check, not just checksum; a file failing decode is flagged for operator attention, not shipped. (07 owns lifecycle; 01 provides the decode-check at seal boundary per contract.) — *cite:* 01.5 §4 (seal-time integrity), conformance item 8.

### G. Manual rebuild procedure (normative floor — outline only, tool deferred)

- [ ] **T-01.40** Document/stub the **manual rebuild procedure** as the normative recovery-floor contract (tool build deferred): (1) decode safely — multi-member-safe, skip truncated trailing member with a **loud warning**, fail loud on a bad tail (some decoders silently discard post-first members — **forbidden**); (2) per-record wire-`v` dispatch; (3) re-dedup by `event_id` (non-money) / `transaction_id` (purchase); (4) **re-apply the `ERASURE_LEDGER` filter** (per-game keyed-hash of `user_id`, skip on executed erasure — mandatory); (5) skip quarantine-marked records for aggregate rebuild; (6) re-derive with **logical-day flooring**; (7) reconcile-forward-only (never rewrite a sealed cell downward). — *cite:* 01.5 §5.1, Foundation §6, 00.5 §7.3; conformance items 7 & 10.

## 2. Cross-phase dependencies

- **`GAME` / credentials — 01 stores, phase 10 writes (Foundation §5).** The `GAME` row + `sdk_key`/`server_credential` scalars are 01-owned *storage* but the registration/rotation *writer* is phase 10's admin API. T-01.17 (auth) and every ingest task **read** `GAME`; they need at least the T-01.6 seed path to run before phase 10 lands. `provenance` derivation depends on the credential-class model (Foundation §4.5) whose full 1..N child entities are phase 10.
- **`USER_SPINE.first_seen` / bitmap — written by 02, never by 01 (Q1, bridge 02.5).** 01's step 7 hands the routed session record to 02 which does sequence A (`first_seen` insert-if-absent) then B (bitmap bit). 01 must NOT seed the spine; it only emits the `no_spine_row` advisory tally for non-session events (T-01.27). Reader dependency: 01's `no_spine_row` check reads `USER_SPINE` (owned by 04, written by 02).
- **Raw file lifecycle — 01 appends, 07 owns (bridge 01.5 §1).** 01 executes step-4 append + seal-time decode-verify (T-01.32..T-01.39); **07 owns** seal→upload→verify→bookkeeping→delete and `UPLOAD_BOOKKEEPING`. The handoff needs no lock: 01 only writes open files, 07 only ships sealed files. Rebuild-tooling erasure-refilter step (T-01.40 step 4) depends on `ERASURE_LEDGER` owned by 00.5/phase-10 (Q7).
- **Purchase durable gate — 01 sequences, 05 writes (Foundation §3.1 step 6).** 01 owns *where* the `transaction_id` gate sits in the op-order (before any hot write); 05 owns the durable `PURCHASE_IDEMPOTENCY` insert-if-absent write + conflict semantics. Blocks full purchase-path testing until 05 exists.
- **`EXCEPTION_TALLY` — 01 owns, all stories write into it.** 01 owns the table + writes tallies for other kinds' quarantines, but the reason-enum values `negative_offset` (04 via 02), `fx_stale_rate_used`/`fx_unconverted` (05), `rate_limited` (00.5) are *produced* by those phases through 01's tally path. T-01.4's enum must include all of them up front.

## 4. Open considerations / flags for /plan

- **OF-1 — Missing `event_id` on a generic event (01 §Design open Q1).** Design *default* = drop-and-tally under `unparseable` (an undedupable event would void the §F 24 h guarantee). The deeper sheet's "name + parseable body is enough" reading would instead accept-without-dedup. **Implemented as drop per the design default; flag for /plan if accept-undeduped is wanted.** Do not silently pick the other branch.
- **OF-2 — `first_seen` = `LEAST` merge direction (Foundation §3.2.1 mixed-`cat`).** The catalog flush MUST lower `first_seen` on an earlier observed value — the one field that merges by min, not max. Easy to get backward and would silently corrupt cohort/first-seen reads downstream. Called out as load-bearing in T-01.5.
- **OF-3 — Grand total as read-time Σ vs stored cell (01 §Design open Q3).** §4 of the story lists a stored per-game×day grand total; the design derives it read-time from `EVENT_DAY_COUNT` (cap-bounded ≤500 terms, drift-free, raw-re-scan-free). **Implemented read-time (no stored cell); flag if a stored cell is preferred.**
- **OF-4 — Class-N Redis-Cluster hash-tag (Foundation §3.2.1 schema note).** Not 01's cells (01 is class M + mixed-`cat`), but if Redis is ever sharded the flusher's cross-domain assumptions must be re-checked; single-node posture (current) is unaffected. Noted for /plan awareness only.
- **OF-5 — Group-commit append-writer sizing (01.5 §4).** The single-writer-per-open-file + group-commit design is normative but the buffer/coalesce window sizing, backpressure when a writer lags, and the writer↔worker handoff mechanism are implementation-level (hot-path performance). Needs a concrete design at /plan: a slow disk fsync must not stall all workers for that game.
- **OF-6 — Seal-time decode-verify ownership seam (01.5 §1/§4).** The contract puts the end-to-end decode-check at the seal boundary "before upload-eligible" — but seal/lifecycle is 07's job while the append is 01's. /plan must decide whether the decode-verify runs in 01's seal-flush path or 07's nightly path (contract says "nightly/seal path"); pick one owner to avoid a gap where neither runs it.
- **OF-7 — Rebuild tool deferred but contract normative (01.5 §5.1).** v1 ships **no automated replay**; T-01.40 stubs the procedure as documented contract only. The mandatory `ERASURE_LEDGER` refilter step (step 4) depends on the ledger existing (00.5 §7 / phase 10). Flag: "disposable-but-recoverable" is only real once the ledger schema is present, even though the tool is deferred.
- **OF-8 — PII default-DENY denylist content (§6 / 00.5 §9).** The default `pii_prop_denylist` is non-empty (`[email, ip, phone, name, address, …]`) as of 2026-07-17 — the exact key list and the value-scrubber regex set are policy that /plan should pin explicitly (a too-broad regex strips legitimate props; too-narrow leaks PII into a 90-day raw file). Already-registered keys need the one-shot catalog-scrub tool (00.5 §9) which is a separate operator action, not part of this phase's ingest path.
- **OF-9 — Server-clock discipline is a deployment requirement, not code (Foundation §4.2).** Slewing NTP (`chronyd`, bounded `maxslewrate`, never step-on-start) is mandated for skew + seal correctness. 01's two software guards (26 h sanity clamp → `time_fallback`; backward-`server_received_time` monotonicity alarm) are in-scope tasks (T-01.22 + an alert), but the daemon itself is an infra/deploy prerequisite that must be in the docker-compose/ops runbook, not assumed.
