# Bridge 02.5 — Activeness / Spine Write-Delegation Contract (01 · 02 → 04)

**Feature**: 001-analytics-platform · **Layer**: design bridge (cross-story contract) · **Status**: Design-complete (2026-07-17)
**Parties**: Phase 04 — **owns** `USER_SPINE` (semantics of `first_seen` + `active_days_bitmap`) and both delegated sequences · Phase 02 — **executes sequences A and B** in its session-start path (Phase 01's front-door executes neither — §6 ratification, 2026-07-17).
**Grounding**: Foundation §1.3, §3.1 steps 5/7, §5, §6, §9.4; [003 sessions design](../../003-sessions/design.md) step 7; [005 retention design](../../005-retention/design.md) sequences A/B, DD-1, OQ-1–3.
**Why a bridge**: the spine writes are the system's one cross-story durable-write delegation — 02 executes two 04-owned durable-immediate sequences whose transition-reporting, ordering, and crash semantics must stay **identical across both sequences**. Both sides flagged it; this file is normative for both.

## 1. Delegation map

| Sequence | Trigger | Executor | 04-owned semantics |
|---|---|---|---|
| **A — first-session seed** | first accepted **`session`** event carrying a `user_id` (**RATIFIED 2026-07-17**, §6 below; Foundation §5/§9.4 updated) | 02 session path, step 7, immediately before B for the same event | `first_seen` insert-if-absent (write-once; value = **corrected session start**) → *iff created*: `COHORT.cohort_size` increment |
| **B — session-start bit** | accepted `session` event only (Foundation §7: activeness = session-start) | 02 session path, step 7, after A for the same event | offset math → atomic set-once bit → *iff 0→1 transition*: `RETENTION_CELL` increment |

`session` is the **only** kind that reaches **either** sequence — no other kind seeds the spine or sets a bit. A **non-session** accepted event referencing a `user_id` with no spine row proceeds normally (its own aggregates never require the spine) and tallies **`no_spine_row`** (advisory — detects SDK integrations that skip session events; may fire transiently on in-batch reordering, so it is a signal, not an error). Events carrying only `anon_id` touch neither sequence (Foundation §4.6 — no aliasing in v1).

## 2. Sequence A (normative)

1. **7a** — `USER_SPINE` insert-if-absent of `(game_id, user_id, first_seen = corrected session_start)`; the insert **reports created?** and runs **immediately before 7b** within the same session event's processing (spine row before offset math — Foundation §8.4). Seeding from the corrected **start** time — the same value 7b's offset math uses — makes the seeding event's own offset 0 by construction.
2. **8a** — *only if created*: rehydrate-on-miss, then increment `size` in `{game_id}:ret:{c}`, `c = logical_day(first_seen)` (Foundation §4.7) = this session's corrected start day. `c` is open by construction — 02's step-5 gate governs on the **start** day (02 Design), so a session whose start day is sealed never reaches sequence A at all.

## 3. Sequence B (normative)

1. **7b — offset math**: `offset = logical_day(corrected session_start) − logical_day(first_seen)` (Foundation §4.7; the platform `reporting_offset` shifts both operands equally, so the difference and the §4 negative bound are translation-invariant — no change to the guard geometry). The spine row is guaranteed by 7a **for this same event**. Guards: negative offset → §4; over-horizon → §5.
2. **7b′ — set-once bit (durable-immediate)**: one atomic conditional write — *set bit `offset` iff unset, report the transition*. Already set → **full no-op**: 8b is skipped entirely. This single guard is what makes dedup misses beyond 24 h, reprocessing, and midnight-span splits safe (FR-016).
3. **8b** — *only on a reported 0→1 transition*: rehydrate-on-miss, then increment `cell:{c}:{offset}` in `{game_id}:ret:{d}`, `d = c + offset` = this event's own corrected start day (open — this event passed step 5 for `d`).

## 4. Shared crash / transition semantics (identical for BOTH sequences — the reason this bridge exists)

- **Durable row/bit first, counter second.** A crash between them redelivers the job, which stops at step 6 (`event_id` marker already set): the increment is lost, so the projection runs **behind** the spine truth — never ahead. Every interleaving fails conservative: phantom cohort members / phantom retention are impossible; the cost is a detectable undercount.
- **Healing is the Foundation §1.3 lever**: re-project `COHORT.cohort_size` / `RETENTION_CELL` (and `ACTIVE_USER_DAY`) from a **spine re-scan** — never a raw re-scan. The same lever covers Redis loss ≤ one flush window (Foundation §6).
- **Projections lag, never lead**: 04/06 may observe a set bit before the corresponding counter flush lands; the spine is the truth (Foundation §1.3). Both executors must preserve this direction — inverting it in either path would make overcounts undetectable.

## 5. Boundary rules (normative, identical for both sequences)

| Rule | Contract |
|---|---|
| **Negative offset** | corrected session-start day **earlier** than the user's `first_seen` day. One surviving cause (first-session seeding — §6 — structurally eliminated the late-`reconciled`-first-touch cause, since the seed now derives from the same start timestamp the offset math uses): an in-grace processing race — a later-day session seeds `first_seen` before an earlier-day session of the same user processes. Bounded `≥ −2` by the 48 h window geometry (both start days must be open). **Rule: skip the bit AND the counter; tally `negative_offset` (Foundation §1.2 enum — amendment landed); never back-date the write-once `first_seen`; the session still counts in 02's day aggregates** (count/duration/`act` membership are unaffected). *Rejected*: clamping to bit 0 — fabricates Day-0 activity. |
| **Over-horizon** | bitmap spans `max(retention_day_targets) + ~15 d` headroom. `offset >` span ⇒ skip bit, no counter — silent no-op **by design** (untracked, not exceptional); widening the horizon is forward-only ("tracking begins <date>"). |
| **Sealed day — full stop** | a sealed corrected day stops the event at Foundation §3.1 step 5 (quarantine + `sealed_late`): **no bit, no counter, no `first_seen`** — neither sequence runs. A user whose genuinely-first session arrives sealed-late anchors at their next in-grace **session** event (04 OQ-2, adopted: Foundation wins). |
| **Midnight span** | one session, one bit: the **start** day's. 02's pro-rata duration split never re-enters the spine or retention. |

## 6. DECISION RECORD — `first_seen` = first accepted `session` event (RATIFIED 2026-07-17, research-locked)

**The tension** (now closed): Foundation §5 originally seated sequence A at the front-door on **any** accepted event; the retention metrics sheet read FR-015 as **first session** only. A research pass across GA4, Amplitude, Mixpanel, GameAnalytics, and Adjust settled it for the **first-session** reading — the former fallback row became the rule; Foundation §5/§9.4 and 04 DD-1/OQ-1 are updated accordingly.

**Decision.** Sequence A executes in 02's session path, immediately before 7b, on the first accepted `session` event; seed value = **corrected session start** (§2). 01's front-door seeds nothing.

**Why (the symmetry principle).** Every surveyed product keeps the cohort-anchor event and the return event in the same activity domain: GameAnalytics (install date ≡ first-session date; "D0R is always 1.0"), Adjust (install = first app open = first session; retained = ≥ 1 session that day ÷ cohort installs), Amplitude (any-event anchor with any-event return — symmetric the other way), Mixpanel (user-chosen birth + return events, cohorted by the birth event), GA4 (`first_open` coincides with `session_start` — every event lives inside a session, so the distinction collapses). With our locked invariant *activeness = session-start* (Foundation §7), the previously-adopted any-event anchor was the one asymmetric configuration no surveyed product ships: D0 < 100 % by construction, and never-sessioned users permanently deflating every D_N against industry benchmarks that are all computed on install-equals-first-session semantics.

**What the ratification buys.** D0 = 100 % is now an invariant (the seeding session itself sets bit 0 — 7a and 7b′ fire within one event); `COHORT.cohort_size ≡ RETENTION_CELL(c, 0)` becomes a free cross-counter integrity check; cohort denominators are directly comparable to GameAnalytics/Adjust D1/D7/D30 benchmarks; negative-offset cause (i) is structurally eliminated (§5).

**Accepted consequences (stated honestly).**
- Never-sessioned users (server-only emitters, purchase-before-first-session, misintegrated SDKs) get **no spine row**: 05/06 resolve `days_since_install` / `install_cohort` to `unknown` (first-class); 03 skips `BALANCE_SNAPSHOT` writes for them; each such accepted event tallies `no_spine_row` (advisory).
- **The money seam is spine-independent** (05.5 §3 amended): `PURCHASE_IDEMPOTENCY` / `PAYER_SPINE_EXT` / `PAYER_PERIOD_SPEND` key on `(game_id, user_id)` as a **logical** association, not an enforced spine-parent dependency — a payer may exist with no spine row, and `first_purchase_day` may precede `first_seen` (purchase-before-first-session: valid, documented). Money is never blocked on engagement state.
- A user whose genuinely-first session arrives sealed-late anchors at their next in-grace session (04 OQ-2 posture unchanged).

## 7. Worked example (one user, both sequences, every guard)

User `u1`, game `g`, `retention_day_targets = [1, 7, 30]` (bitmap span 45). Today = 07-17.

## 8. Conformance checklist (what a reviewer verifies in 01/02/04)

- [ ] Sequence A runs in 02's session path, immediately before 7b, for `session` kind only; the increment fires only on *created*; **no seeding site exists anywhere else** (01's front-door has none).
- [ ] `first_seen` is seeded from the corrected session **start** time — the same value 7b's offset math uses.
- [ ] Sequence B fires only for `session` kind; increment fires only on a *reported transition*.
- [ ] Both sequences order durable write ≺ counter; neither inverts on retry.
- [ ] Negative-offset and over-horizon guards present in 02's executor with 04's exact semantics; `negative_offset` tallied.
- [ ] No path creates `first_seen`, a bit, or a counter for a sealed corrected day.
- [ ] Non-session accepted events never touch the spine; a missing spine row tallies `no_spine_row` (advisory) and never blocks the event's own processing.
